## 概述

Bian Que是快手团队开源的一款用于大规模在线引擎系统（搜索、推荐、广告）自动化运维的Agent框架。该框架通过创新的灵活Skill编排机制，解决了基于LLM的Agent在实际运维场景中的部署瓶颈——如何为每个运维事件精准选择相关的数据源和知识库。

在快手的电商搜索引擎上线6个月，Bian Que取得了显著成效：告警量减少75%，根因分析准确率达80%，平均修复时间（MTTR）压缩超过50%，实际需要人工处理的告警减少约95%。

## 核心创新

### 1. 统一的运维范式

Bian Que将大规模在线系统的运维工作抽象为三种典型模式，形成三层防御体系：

- **发布拦截**：在代码发布前自动检查，防止有问题的代码上线
- **主动检查**：定期扫描系统状态，提前发现潜在问题
- **告警根因分析**：收到告警后自动诊断问题根源，提供修复建议

这三种模式覆盖了从预防到响应的完整运维闭环，将复杂的日常运维工作标准化、系统化。

### 2. 灵活的Skill编排机制

这是Bian Que的核心创新。每个Skill是一个可编排的业务单元，明确指定在特定业务模块上下文中需要检索的数据和知识。

**Skill结构定义**：
```
Skill = ⟨LoadDataSchema, Prompt, Meta⟩
```

- **LoadDataSchema**：JSON格式的数据规范，声明需要调用的数据源（指标、日志、变更事件）和知识库查询
- **Prompt**：结构化推理模板，定义如何对检索到的数据和知识进行分析
- **Meta**：元数据，包含名称、版本、描述和标签

**Flexible Skill生成算法**：
1. 输入：运营事件e、源描述符L、能力描述符C和参考Skills
2. 通过LLM生成候选Skill
3. 执行LoadDataSchema验证
4. 如有错误，反馈给LLM重新生成，最多重试3次

这种机制的优势在于：
- 自动化：LLM根据事件特征自动生成Skill，减少人工配置工作
- 灵活性：通过自然语言指令即可修正和优化Skill
- 上下文感知：针对特定业务模块组合定制数据检索策略

### 3. 统一的自演进机制

Bian Que设计了一个巧妙的反馈循环，让知识库和Skill协同演进。

**反馈机制公式**：
```
f → {MemoryWrite(c) → KnowledgeDistill(c), SkillRefine({si}, f)}
```

每个Agent执行时产生案例记录 `c = (e, {si}, D, K, o, f)`，其中：
- e：运营事件
- {si}：使用的Skills集合
- D, K：检索到的数据和知识
- o：Agent输出
- f：反馈信号

反馈信号f同时触发两条并行学习路径：
1. **知识路径**：短期写入记忆存储 → 长期触发自动知识提取
2. **Skill路径**：识别Agent错误的根本原因 → 路由到相应的Skill生命周期操作

两条路径通过构造耦合：更丰富的知识库为新生成或更新的Skills提供更多参考条目，而更高质量的Skills为知识蒸馏产生更清晰的案例记录。

## 实战效果

### 生产环境部署数据

在快手电商搜索引擎（日均活跃用户数亿级）的6个月实际运行中：

- **告警量**：减少75%
- **非可操作告警比例**：从80%降至15%
- **人工处理告警**：从100%降至约5%（减少95%的pager负载）
- **根因分析准确率**：80%
- **诊断响应速度**：95%的案例在5分钟内得到响应
- **平均修复时间（MTTR）**：压缩超过50%

### 离线评估结果

**Flexible Skill机制评估**：
- pass@1：78.8%
- pass@5：94.2%
- 加上人工反馈后：
  - pass@1提升至97.1%
  - pass@3达到99.0%

**消融研究**：
- 移除Flexible Skill机制：pass@5从94.2%降至83.7%
- 移除历史知识检索：pass@5从94.2%降至86.5%

**LLM骨干模型比较**：
- 35B参数量级的模型（Qwen3.5-35B-FP8）适合在线部署
- 更小的模型表现出明显较差的性能

## 技术架构

### 框架设计

Bian Que采用矩阵设计：
- **Agent**：场景抽象，每种典型模式（发布拦截、主动检查、告警根因分析）一个Agent
- **Skill**：业务模块编排单元，指定特定业务模块组合需要的数据和知识

单个Agent执行 = 组合Agent的场景逻辑 + 一个或多个匹配的Skills

### 技术栈

- **LLM推理核心**：35B参数量级模型（Qwen3.5-35B-FP8）
- **Skill存储格式**：YAML
- **多索引检索**：Redis + ANN（近似最近邻）服务

### Skill生命周期

1. **生成**：当新业务模块组合首次遇到事件且没有匹配Skill时触发
2. **更新**：通过从业者反馈逐步改进
3. **演进**：通过统一反馈机制自动优化

## 应用价值

### 降低运维成本

- 告警处理人力需求减少95%
- MTTR压缩50%以上，大幅提升系统可用性
- 自动化覆盖从预防到响应的完整闭环

### 提升系统可靠性

- 发布拦截机制防止问题代码上线
- 主动检查提前发现隐患
- 告警根因分析提供精准诊断

### 可扩展性

- 灵活的Skill编排机制支持快速适配新业务模块
- 自演进机制持续优化性能
- 开源代码便于社区贡献和二次开发

## 总结

Bian Que框架通过"统一的运维范式 + 灵活的Skill编排 + 自演进机制"三位一体的设计，成功解决了LLM Agent在大规模在线系统运维中的核心挑战。其实战效果证明了该框架的有效性：在保证高准确率的同时，大幅降低运维成本，提升系统可靠性。

对于希望将LLM Agent应用于生产环境的团队，Bian Que提供了宝贵的实践参考：关键不在于模型能力，而在于如何精准地编排数据与知识，如何建立有效的自演进机制。
