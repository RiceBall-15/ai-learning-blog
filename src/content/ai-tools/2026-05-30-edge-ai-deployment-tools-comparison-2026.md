## 三、逐工具深度评测

### 3.1 Ollama —— 端侧部署的"Docker"

**架构设计：**

```
┌────────────────────────────────────────────────────┐
│                 Ollama 架构                         │
├────────────────────────────────────────────────────┤
│                                                     │
│  ┌──────────────────────────────────┐              │
│  │         CLI / REST API            │              │
│  │  ollama run / ollama pull         │              │
│  └───────────────┬──────────────────┘              │
│                  │                                   │
│  ┌───────────────▼──────────────────┐              │
│  │         Ollama Server (Go)        │              │
│  │  · 模型管理 (pull/push/list)      │              │
│  │  · 推理调度                       │              │
│  │  · 会话管理                       │              │
│  └───────────────┬──────────────────┘              │
│                  │                                   │
│  ┌───────────────▼──────────────────┐              │
│  │     llama.cpp (C++ Backend)       │              │
│  │  · GGUF模型加载                   │              │
│  │  · CPU/GPU推理                    │              │
│  │  · KV Cache管理                   │              │
│  └──────────────────────────────────┘              │
│                                                     │
│  特点: 封装了llama.cpp，提供类Docker的体验           │
│  模型库: Ollama Registry (3000+模型)                │
│                                                     │
└────────────────────────────────────────────────────┘
```

**优势：**
- 开箱即用，一条命令即可运行模型
- 模型管理类似Docker，pull/run/push心智模型一致
- 活跃的社区和丰富的模型库
- 原生支持多模态模型

**不足：**
- 高级用户对推理参数的控制有限
- 多GPU负载均衡能力弱于vLLM
- 不支持连续批处理（Continuous Batching）

**适合场景：** 个人开发者、快速原型验证、教学演示

### 3.3 MLX —— Apple生态的最优解

**架构设计：**

```
┌────────────────────────────────────────────────────────────────┐
│                    MLX 架构                                     │
├────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────┐     │
│  │                   Python API                           │     │
│  │  import mlx.core as mx                                │     │
│  │  import mlx_lm as lm                                  │     │
│  └──────────────────────┬───────────────────────────────┘     │
│                         │                                       │
│  ┌──────────────────────▼───────────────────────────────┐     │
│  │                   MLX Core                             │     │
│  │                                                        │     │
│  │  ┌──────────────┐    ┌──────────────┐                │     │
│  │  │ 统一内存架构   │───▶│ Metal后端     │                │     │
│  │  │ (Zero-copy)  │    │ (GPU直接访问) │                │     │
│  │  └──────────────┘    └──────────────┘                │     │
│  │                                                        │     │
│  │  关键特性:                                              │     │
│  │  · CPU/GPU零拷贝：数据在统一内存中，无需CPU↔GPU传输    │     │
│  │  · 动态计算图：类似PyTorch的Eager模式                  │     │
│  │  · 自动微分：内置autograd                              │     │
│  └──────────────────────────────────────────────────────┘     │
│                                                                 │
│  性能优势:                                                       │
│  · M4 Max上运行Llama3.1-70B: ~30 tok/s                        │
│  · M3 Pro上运行Llama3.1-8B: ~45 tok/s                         │
│  · 统一内存架构避免了GPU显存限制                                 │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

**MLX独有优势：统一内存架构**

```
传统GPU推理 (NVIDIA):
┌──────────┐     PCIe传输     ┌──────────┐
│ CPU 内存  │ ◀══════════════▶ │ GPU 显存  │
│ (数据)    │   带宽限制/延迟    │ (计算)    │
└──────────┘                  └──────────┘
  128GB DDR5                  24GB VRAM
  (可用但慢)                   (快但小)

Apple MLX:
┌──────────────────────────────────────┐
│         统一内存 (Unified Memory)      │
│  ┌──────────┐     ┌──────────┐      │
│  │ CPU 逻辑  │     │ GPU 逻辑  │      │
│  │          │     │          │      │
│  │ 直接访问  │◀───▶│ 直接访问  │      │
│  └──────────┘     └──────────┘      │
│  192GB (M4 Ultra)                    │
│  无传输延迟，零拷贝                    │
└──────────────────────────────────────┘

这意味着: 在M4 Ultra上可以无量化运行70B模型 (140GB原始权重)
          在M2 Pro上可以流畅运行13B量化模型
```

**适合场景：** Mac用户、Apple Silicon设备、需要GPU但不想管理显存的场景

### 3.4 LM Studio —— 最佳桌面体验

**核心特点：**

- 全图形化界面，零命令行
- 内置模型下载和管理
- 支持多模型切换
- OpenAI兼容API服务器
- 支持本地RAG（文档对话）

**性能表现：** 底层基于llama.cpp，性能接近但略低于直接使用llama.cpp。

**适合场景：** 非技术用户、快速体验、本地文档问答

**架构对比：**

```
┌────────────────────────────────────────────────────────────────┐
│              vLLM vs SGLang 架构对比                             │
├────────────────────────────────────────────────────────────────┤
│                                                                 │

│  ┌──────────────────────────────────────────────┐             │

│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐        │             │

│  │  │(长文本) │ │(短文本) │ │(中等)   │        │             │

│  ┌──────────────────────────────────────────────┐             │
```

## 六、实战推荐：不同场景的最佳组合

### 6.1 个人开发者推荐配置

```bash
# Mac用户
# 安装MLX
pip install mlx mlx-lm

# 运行模型
mlx_lm.generate --model mlx-community/Meta-Llama-3.1-8B-Instruct-4bit \
  --prompt "你好，请介绍一下你自己"

# 或使用Ollama（更简单的体验）
curl -fsSL https://ollama.com/install.sh | sh
ollama run llama3.1:8b
```

### 6.2 团队协作推荐配置

```bash
# 使用Ollama作为本地模型服务
# docker-compose.yml
version: '3.8'
services:
  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

  # 前端应用
  app:
    build: ./app
    ports:
      - "3000:3000"
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    depends_on:
      - ollama

volumes:
  ollama_data:
```

### 6.3 生产环境推荐配置

```bash
# 使用vLLM部署生产级API服务
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-70B-Instruct \
  --tensor-parallel-size 4 \
```
