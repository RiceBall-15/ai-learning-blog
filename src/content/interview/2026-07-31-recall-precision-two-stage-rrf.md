# 怎么保证召回是准的：precision/recall 与宽召回严精排

> 「你怎么保证召回准确率？」——如果只答「用了 RRF 融合」，面试官会觉得你只是用了个算法。
>
> 准确率不是靠某个算法保证的，是靠一套**两阶段架构 + 阈值地板 + 度量回归 + 反馈闭环**。而第一步——也是最能立刻区分深浅的一步——是**先把「准确率」这个词拆清楚**。

## 一、先厘清「准确率」到底指什么

```text
召回质量有两个方向，常被笼统说成「准确率」：

  Precision（精确率）：召回的 K 条里，有多少是真相关的     → 去噪能力
  Recall   （召回率）：所有相关的记忆里，有多少被召回了     → 不漏能力

两者天然权衡（tradeoff）：
  召回越多（想提 Recall）→ 越容易混入噪声（Precision 降）
  卡得越严（想提 Precision）→ 越容易漏掉相关的（Recall 降）
```

**为什么这一步这么重要**：因为两者的**优化方向完全相反**。

- 用户抱怨「明明说过却没记住」→ 这是 **recall 问题**，要**放宽**
- 用户抱怨「答得跑偏、提了没用的事」→ 这是 **precision 问题**，要**收紧**

资浅只说「准确率」，然后拍脑袋调参数；资深先定位是哪一边的问题，再决定往哪个方向调。

## 二、核心武器：两阶段「宽召回 → 严精排」

既然 precision 和 recall 天然矛盾，一步做不到又准又全，那就**分两阶段把矛盾解开**：

```text
阶段 1 召回（目标：高 Recall，宁多勿漏）
  双通道 dense ∥ sparse，各取 topK（K 取大，如 50）
  心态：把可能相关的都捞上来，不怕多，怕漏
  ── 这一阶段不追求准，追求全

阶段 2 精排 + 过滤（目标：高 Precision，去噪）
  RRF 融合排名
  → 回表权威库确认（向量可能落后）
  → scope / TTL / tombstone 过滤
  → minSimilarity 阈值（precision 地板：低于阈值宁可不召）
  → × effectiveImportance 重排（重要度 × 衰减）
  → 取 TopK'（K' 取小，如 5）
  心态：从「捞上来的一堆」里精选真正该注入的少数
  ── 这一阶段不追求全，追求准
```

**一句话**：**召回宽、精排严**——第一阶段用大 K 保 recall，第二阶段用阈值 + 重排 + 小 K' 保 precision。

这就是把矛盾解开的工程手法，也是这一题的核心答案。

### 完整流水线伪码

```text
// R1 并行检索（单路失败保留另一路）
denseResults  = denseKNN(query, topK=50)      // 语义向量
sparseResults = bm25(query, topK=50)          // 关键词

// R2 RRF 融合
k = 60
for doc in union(denseResults, sparseResults):
  score = 0
  if doc in denseResults:  score += 1/(k + denseRank(doc))
  if doc in sparseResults: score += 1/(k + sparseRank(doc))
  doc.rrfScore = score

// R2 精排（顺序不能错！）
ranked = candidates
  .filter(回表权威库确认存在)                  // 向量可能落后，回表是闸
  .filter(scope 确认 tenant/object)            // 防脏、防串用户
  .filter(TTL 未过期)
  .filter(非 tombstone)
  .filter(similarity ≥ minSimilarity)          // precision 地板
  .map(d => d.finalScore = d.rrfScore × effectiveImportance(d))
  .sortBy(finalScore desc)
  .take(5)                                     // 小 K'

// R3 注入
output = format(ranked, maxChars)              // 超长从低分剔除，保高价值
```

## 三、为什么用 RRF 而不是加权平均

双通道的分数**量纲不可比**：dense 是余弦相似度（0–1 有界），sparse 是 BM25（无上界）。直接加权平均毫无意义，而且需要先有大规模标注集来校准权重。

**既然分数不可比，那就比排名**：

```text
RRF（Reciprocal Rank Fusion）：score(d) = Σ 1/(k + rank(d))
```

三个好处：

1. **免校准**——不需要先有标注集就能起步
2. **多路命中增益**——一个文档被两路都召回、排名都靠前，分数自然累加
3. **可解释**——为什么这条排前面，能说清

### k 值怎么选

```text
k 太小 → 头部排名权重过重（第 1 名压倒一切）
k 太大 → 过于平均（排名差异被抹平）
经验值 60；有标注集后离线扫参
```

### 三种融合方案的取舍

| 方案 | 优点 | 缺点 | 何时用 |
|------|------|------|--------|
| 加权平均 | 简单 | 量纲不可比、需校准 | 不推荐（除非单路） |
| **RRF** | 免校准、多路增益、可解释 | 不利用分数绝对值 | **默认**，无标注集时 |
| 学习排序 | 效果最优 | 需标注集、需训练、重 | 有标注集且量大时 |

**不默认上 LLM rerank**：贵、慢、加首包。只有当有标注集证明收益显著、且场景对延迟不敏感时才上。

## 四、双通道为什么必须互补

```text
dense（语义向量）：强在模糊匹配，弱在专有名词（药名/地名/型号）
sparse（BM25）   ：强在精确关键词匹配
```

典型 badcase：用户提到某个具体型号或药名，dense 会召回「语义相近但不是那个」的记忆，只有 sparse 能精确命中。这就是双通道互补的核心价值——**不是为了看起来高级，是为了补对方的短板**。

要不要加第三路（如全文检索）？按收益算——每多一路都增加延迟和成本，双通道够用时不上第三路。

## 五、Precision 地板：minSimilarity 阈值

```text
minSimilarity 是「宁缺毋滥」的闸门：低于阈值的候选一律丢弃

阈值太高 → precision 高，但可能把该召的漏了（recall 降）
阈值太低 → recall 高，但混入噪声（precision 降 → 负迁移风险）

怎么定（不是拍脑袋）：
  离线扫参 + 负迁移率约束
  → 阈值要低到「不漏」，但高到「recall on 的满意度 ≥ recall off」
  → 即：宁可少召，也不能让噪声把回答带偏
```

## 六、相似度高 ≠ 这条记忆对

这是很容易忽略但被追问就露馅的一点：

> **相似度只说「语义像」，不说「有效 / 未过期 / 不矛盾」。**

一条旧偏好可能语义上跟当前 query 高度相关，但它已经被用户改口覆盖了（见上一篇的冲突裁决）、或者已经过 TTL、或者已被删除但向量投影残留。

所以相似度**必须叠加**：回表权威库确认 + TTL + 衰减 + 版本状态 + scope 过滤。

**相似度是必要不充分条件。**

## 七、时间预算：召回绝不能拖死对话

准确率再高，拖死首包也是不可用的。所以召回有**硬预算 + 软失败**：

```text
τ1 通道截止：dense/sparse 必须在 τ1 内返回，超时用已完成的一路
τ2 融合截止：RRF + 精排必须在 τ2 内完成，超时用已融合的部分
τ3 节点截止：整个召回节点必须在 τ3 内完成

任一超时 → SOFT_FAIL + degraded=true → 主 LLM 用空上下文继续

不变式：召回超时 ≠ 整图失败
```

降级模式要打标，主 LLM 才知道「这次没记忆」：

```text
DENSE_ONLY    sparse 挂了，只用 dense
SPARSE_ONLY   dense 挂了，只用 sparse
DEGRADED      整体超时，空上下文继续
```

> **最高原则**：宁可没记忆，也要保首包。记忆是增强，不能绑架可用性。

## 八、负迁移：比「召不准」更危险的失败

**负迁移** = 加了召回反而答得更糟。因为召回到的是过期 / 错误 / 无关记忆，注入后把模型带偏。

**为什么很多人发现不了**：只看召回命中率。

> **命中率只证明「召到了」，不证明「有用」。**

### 必须用配对检验，不能比均值

这是一个统计上的关键细节：

```text
ablation(evalQueries):
  diffs = []
  for q in evalQueries:
    s_on  = judge(answer(q, recall=ON))
    s_off = judge(answer(q, recall=OFF))
    diffs.add(s_on - s_off)         // ★ 同一 query 的配对差值，消掉 query 难度差异

  if mean(diffs) <= 0 or not significant(diffs):
    flag(NEGATIVE_TRANSFER)

  negTransferRate = count(d < 0 for d in diffs) / len(diffs)   // 多少比例被带偏
```

**为什么不能比两组独立均值**：均值可能被**少数大涨掩盖多数小跌**——整体均值上升了，但实际上 60% 的 query 变差了。所以要看**配对差值的分布**和**负迁移率**，不是看均值。

## 九、Agentic RAG：不是每次都召

```text
// 条件节点先判 query 是否值得召回
if query.containsPersonalOrPreferenceOrEntity():   // 个人/偏好/带实体
  → 走召回支路
else:
  → 跳过召回（省成本、省延迟，避免无意义检索）
```

由 Agent 决定是否检索，而不是无脑每次都召。这既省成本，也**减少了引入噪声的机会**——对 precision 也是正贡献。

## 十、「保证准确率」是个闭环，不是单点

```text
① 离线度量：固定评测集跑 Recall@K / Precision@K / MRR / nDCG
② 在线兜底：minSimilarity 地板 + 负迁移消融监测
③ 反馈闭环：运营标错回写 → 降权 / 调阈值 → 回归验证
④ 分场景互补：专有名词靠 sparse、模糊语义靠 dense
```

> 「保证准确率」= **两阶段架构 + precision 地板 + 离线度量 + 负迁移监测 + 反馈闭环**。
> 不是「检索算法多牛」，是这套工程体系。

## 十一、生产踩坑

### 坑 1：一加记忆，首包从 800ms 飙到 3s

**排查**：召回在主路径串行调用，且无时间预算。
**修复**：① 硬预算 τ1/τ2/τ3 + 软失败；② 召回与主 LLM 并行（召回是独立支路）；③ 双通道并行而非串行。
**验证**：首包回到预算内，超时走 degraded 不拖主对话。

### 坑 2：召回全但噪声多（recall 高、precision 低）

**现象**：该召的都召到了，但也混进一堆无关记忆，回答发散。
**排查**：只做了召回，没做精排 / 阈值。
**修复**：加 minSimilarity 地板 + importance 重排 + 缩小注入 K'。
**验证**：Precision@K 上升、负迁移率下降。

### 坑 3：阈值定太高把该召的漏了（precision 高、recall 低）

**现象**：用户明明说过，但召不到。
**修复**：降阈值，靠**精排去噪**而不是靠阈值硬卡；专有名词场景加 sparse 兜底。
**验证**：Recall@K 上升且负迁移不回升。

### 坑 4：专有名词语义检索差

**现象**：药名 / 型号 / 地名召回不准。
**根因**：dense 对专有名词弱（语义近但不一致）。
**修复**：sparse/BM25 通道兜底精确匹配。

### 坑 5：相似度高但其实过期 / 已删

**修复**：相似度必须叠加回表 + TTL + 衰减 + 版本 + scope 过滤。
**验证**：改口 / 过期后不再召回旧值。

### 坑 6：「有时有记忆有时没有」

**排查**：查 degraded 标记（是否超时降级）+ 查采集链路（记忆是否根本没写进去）。
**关键**：要区分「**召回降级**」（调预算 / 性能）和「**记忆缺失**」（调采集链路）——两者现象一样、根因完全不同。

## 十二、追问与反陷阱

| 追问 | 陷阱 | 口径 |
|------|------|------|
| 「你说召回准确率，指 precision 还是 recall？」 | 笼统答「准确率」 | 「要区分：precision = 召回的准不准（去噪），recall = 该召的漏没漏（不漏），两者天然权衡。优化方向相反——漏召是 recall 问题要放宽，噪声多是 precision 问题要收紧。」 |
| 「怎么同时保证 precision 和 recall？」 | 想一步到位 | 「一步做不到。两阶段解开：召回阶段大 K 保 recall（宽召宁多勿漏），精排阶段 RRF + 阈值 + 重排 + 小 K' 保 precision（去噪）。」 |
| 「为什么用 RRF 不用加权平均？」 | 说不清量纲问题 | 「dense 是有界余弦、sparse 是无上界 BM25，**分数量纲不可比**，加权需要标注集校准。RRF 用排名融合，免校准、多路命中有增益、可解释。」 |
| 「minSimilarity 阈值怎么定？」 | 拍脑袋给个数 | 「离线扫参 + 负迁移率约束：低到不漏、高到 recall on 满意度 ≥ off。宁可少召，不能让噪声带偏回答。」 |
| 「相似度高就一定是对的记忆吗？」 | 只信相似度 | 「不。相似度只说语义像，不保证有效 / 未过期 / 不矛盾。必须叠加回表 + TTL + 衰减 + 版本 + scope。相似度是必要不充分。」 |
| 「你优化了召回，怎么证明有用？」 | 只拿命中率说事 | 「命中率只证明召到了，不证明有用。要做**消融配对检验**（同批 query 分别 on/off 看配对差值 + 显著性）+ 看负迁移率分布，不看均值——均值会被少数大涨掩盖多数小跌。」 |
| 「怎么保证准确率长期不退化？」 | 只做一次调优 | 「闭环：离线固定集度量 + 在线负迁移消融 + 运营标错回写 + 发版回归不许退。」 |

## 十三、一句话速记

> 召回准确率不靠单一算法：先分清 **precision（去噪）与 recall（不漏）**这对矛盾，用**宽召回严精排两阶段**解开——召回大 K 保全、精排用 RRF + 阈值地板 + 重排取小 K' 保准；相似度是必要不充分（要叠加回表/TTL/版本/scope）；再用**配对消融监测负迁移**和标错反馈闭环保证长期不退化。而且永远：宁可没记忆也要保首包。
